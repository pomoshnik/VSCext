# OneC-mini: платформа в духе 1С:Предприятие

| Компонент | Путь | Назначение |
|---|---|---|
| Метаданные (JSON) | `metadata/` | Конфигурация: справочники, документы, регистры… |
| Ядро | `src/OneC.Core` | Модель метаданных, загрузчик JSON, контракты бизнес-логики |
| Бизнес-логика (C#) | `src/BusinessLogic/Modules` | Модули объектов: ПередЗаписью, ПриЗаписи, ПриЗаполнении |
| Публикатор | `tools/Publisher` | JSON-метаданные → схема SQLite (`data/app.db`) |
| Клиент | `client/Client` | Десктоп-клиент на Avalonia: списки, формы, проверка бизнес-логики |

## Быстрый старт

```bash
# 1. Опубликовать конфигурацию в SQLite (аналог F7 в Конфигураторе)
dotnet run --project tools/Publisher -- metadata data/app.db

# 2. Запустить клиент (нужна графическая среда)
dotnet run --project client/Client
```

В VS Code с расширением «Дерево конфигурации 1С» (onec-config-tree-0.2.0.vsix):
откройте эту папку — дерево конфигурации загрузится из `metadata/`.
Правый клик по объекту → «Открыть модуль объекта (C#)» — редактирование бизнес-логики.
Кнопка 🗄 в панели дерева — публикация в SQLite.

## Формат метаданных

```json
{
  "Вид": "Справочник",
  "Имя": "Номенклатура",
  "Синоним": "Номенклатура",
  "Реквизиты": [ { "Имя": "Артикул", "Тип": "Строка" } ],
  "ТабличныеЧасти": [ { "Имя": "Характеристики", "Реквизиты": [...] } ],
  "Формы": [ { "Имя": "ФормаЭлемента" } ]
}
```

Типы: `Строка`, `Число`, `Дата`, `Булево`, `СправочникСсылка.X`, `ДокументСсылка.X`, `ПеречислениеСсылка.X`.

### Стабильные имена таблиц

Каждый объект при создании получает постоянное имя таблицы БД (поле `"Таблица"`
в метаданных): `cat_0000001` — справочники, `doc_` — документы, `enm_` — перечисления,
`inf_`/`acc_` — регистры, `vt_` — табличные части. Переименование объекта **не меняет**
таблицу — данные сохраняются (как в 1С). Публикатор автоматически мигрирует старые
базы: таблицы вида `Спр_Номенклатура` переименовываются в стабильные.

Файл модуля бизнес-логики привязан к объекту полем `"Модуль"`; при переименовании
объекта расширение переименует модуль и обновит код в нём.

## Модуль бизнес-логики (типизированный)

Публикатор генерирует из метаданных файл `src/BusinessLogic/Generated/Метаданные.g.cs`
с типизированными записями и константами перечислений — реквизиты доступны
через точку, работает автодополнение (нужно расширение C# в VS Code):

```csharp
[МодульОбъекта("Справочник.Номенклатура")]
public class Справочник_Номенклатура : МодульСправочникНоменклатура
{
    public override void ПередЗаписью(СправочникНоменклатураЗапись запись, Отказ отказ)
    {
        if (string.IsNullOrWhiteSpace(запись.Артикул))
            отказ.Установить("Поле «Артикул» обязательно.");
    }

    public override void ПриЗаполнении(СправочникНоменклатураЗапись запись)
    {
        запись.СтавкаНДС = Перечисления.СтавкиНДС.НДС20;
    }
}
```

После изменения состава реквизитов выполните публикацию заново —
типы перегенерируются. Нетипизированный вариант (`МодульОбъекта` +
`запись.Строка("Имя")`) тоже продолжает работать.

Клиент вызывает `ПередЗаписью` при сохранении — при отказе запись не выполняется,
сообщения показываются в форме (как в 1С).

## Отладка бизнес-логики

Прямо в «Конфигураторе» (VS Code):

1. Установите расширение **C#** (`ms-dotnettools.csharp`) и .NET SDK 8.
2. Поставьте точку останова в модуле, например в `ПередЗаписью`
   (`src/BusinessLogic/Modules/Справочник.Номенклатура.cs`).
3. Нажмите кнопку 🐞 в панели дерева конфигурации (или F5 →
   «Клиент 1С-мини (отладка)») — клиент соберётся и запустится под отладчиком.
4. В клиенте откройте элемент и нажмите «Записать» — выполнение остановится
   на точке останова: переменные, стек вызовов, пошаговое выполнение.

Отладка публикатора — конфигурация «Публикатор (отладка)».

## Ограничения MVP

- Клиент редактирует справочники и документы (шапка); табличные части, проведение
  документов и движения регистров — в планах.
- Переименование объекта не переименовывает его C#-модуль.

## Автосборка (GitHub Actions)

При каждом пуше в `main` собираются:
- `onec-config-tree-vsix` — расширение VS Code;
- `onec-mini-win-x64` / `onec-mini-linux-x64` — клиент + публикатор + метаданные.

Скачать: вкладка **Actions** → последний запуск → раздел **Artifacts**.
Исходники расширения: каталог `extension/`.

## Визуальный редактор форм

Клик по форме в дереве (например, `Справочники → Номенклатура → Формы → ФормаЭлемента`) открывает визуальный редактор «как в 1С»:

- **слева** — список элементов формы: перетаскивание мышью, кнопки ↑ ↓ ✕;
- **в центре** — живое превью в стиле управляемой формы 1С;
- **справа** — свойства выбранного элемента (Заголовок, ТолькоПросмотр).

Кнопка «Добавить» предлагает стандартные поля (Код/Наименование или Номер/Дата), реквизиты объекта, табличные части и кнопки (Записать и закрыть, Отмена). Изменения сохраняются автоматически в метаданные объекта (`Формы[].Элементы` в JSON).

Клиент «1С-мини» рендерит форму записи по нарисованному макету: порядок полей, заголовки и признак «Только просмотр» берутся из формы `ФормаЭлемента` (справочники) / `ФормаДокумента` (документы). Если форма не нарисована — поля генерируются автоматически, как раньше.

## Окно выбора информационной базы

Клиент «1С-мини» при запуске показывает окно «Запуск 1С-мини» — по образцу окна запуска 1С:Предприятия:

- список зарегистрированных информационных баз (хранится в профиле пользователя: `%APPDATA%/onec-mini/bases.json`);
- кнопки **1С-мини** (открыть базу), **Конфигуратор** (открывает каталог базы в VS Code), **Добавить…**, **Изменить…**, **Удалить**, **Выход**;
- внизу — путь выбранной базы в формате `File="…";`;
- открытие двойным щелчком.

При первом запуске в список автоматически добавляется найденная рядом демо-база. Если передать путь к базе аргументом командной строки (`Client <каталог>`), окно выбора пропускается — так клиент запускается из отладчика (конфигурация «Клиент 1С-мини (отладка)» передаёт `${workspaceFolder}`).
