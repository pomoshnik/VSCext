# OneC-mini: платформа в духе 1С:Предприятие

| Компонент | Путь | Назначение |
|---|---|---|
| Метаданные (JSON) | `metadata/` | Конфигурация: справочники, документы, регистры… |
| Ядро | `src/OneC.Core` | Модель метаданных, загрузчик JSON, контракты бизнес-логики |
| Бизнес-логика (C#) | `src/BusinessLogic/Modules` | Модули объектов: ПередЗаписью, ПриЗаписи, ПриЗаполнении |
| Публикатор | `tools/Publisher` | JSON-метаданные → схема SQLite (`data/app.db`) |
| Клиент | `client/Client` | Десктоп-клиент на Avalonia: списки, формы, проверка бизнес-логики |

## Быстрый старт

```bash
# 1. Опубликовать конфигурацию в SQLite (аналог F7 в Конфигураторе)
dotnet run --project tools/Publisher -- metadata data/app.db

# 2. Запустить клиент (нужна графическая среда)
dotnet run --project client/Client
```

В VS Code с расширением «Дерево конфигурации 1С» (onec-config-tree-0.2.0.vsix):
откройте эту папку — дерево конфигурации загрузится из `metadata/`.
Правый клик по объекту → «Открыть модуль объекта (C#)» — редактирование бизнес-логики.
Кнопка 🗄 в панели дерева — публикация в SQLite.

## Формат метаданных

```json
{
  "Вид": "Справочник",
  "Имя": "Номенклатура",
  "Синоним": "Номенклатура",
  "Реквизиты": [ { "Имя": "Артикул", "Тип": "Строка" } ],
  "ТабличныеЧасти": [ { "Имя": "Характеристики", "Реквизиты": [...] } ],
  "Формы": [ { "Имя": "ФормаЭлемента" } ]
}
```

Типы: `Строка`, `Число`, `Дата`, `Булево`, `СправочникСсылка.X`, `ДокументСсылка.X`, `ПеречислениеСсылка.X`.

### Стабильные имена таблиц

Каждый объект при создании получает постоянное имя таблицы БД (поле `"Таблица"`
в метаданных): `cat_0000001` — справочники, `doc_` — документы, `enm_` — перечисления,
`inf_`/`acc_` — регистры, `vt_` — табличные части. Переименование объекта **не меняет**
таблицу — данные сохраняются (как в 1С). Публикатор автоматически мигрирует старые
базы: таблицы вида `Спр_Номенклатура` переименовываются в стабильные.

Файл модуля бизнес-логики привязан к объекту полем `"Модуль"`; при переименовании
объекта расширение переименует модуль и обновит код в нём.

## Модуль бизнес-логики (типизированный)

Публикатор генерирует из метаданных файл `src/BusinessLogic/Generated/Метаданные.g.cs`
с типизированными записями и константами перечислений — реквизиты доступны
через точку, работает автодополнение (нужно расширение C# в VS Code):

```csharp
[МодульОбъекта("Справочник.Номенклатура")]
public class Справочник_Номенклатура : МодульСправочникНоменклатура
{
    public override void ПередЗаписью(СправочникНоменклатураЗапись запись, Отказ отказ)
    {
        if (string.IsNullOrWhiteSpace(запись.Артикул))
            отказ.Установить("Поле «Артикул» обязательно.");
    }

    public override void ПриЗаполнении(СправочникНоменклатураЗапись запись)
    {
        запись.СтавкаНДС = Перечисления.СтавкиНДС.НДС20;
    }
}
```

После изменения состава реквизитов выполните публикацию заново —
типы перегенерируются. Нетипизированный вариант (`МодульОбъекта` +
`запись.Строка("Имя")`) тоже продолжает работать.

Клиент вызывает `ПередЗаписью` при сохранении — при отказе запись не выполняется,
сообщения показываются в форме (как в 1С).

## Отладка бизнес-логики

Прямо в «Конфигураторе» (VS Code):

1. Установите расширение **C#** (`ms-dotnettools.csharp`) и .NET SDK 10.
2. Поставьте точку останова в модуле, например в `ПередЗаписью`
   (`src/BusinessLogic/Modules/Справочник.Номенклатура.cs`).
3. Нажмите кнопку 🐞 в панели дерева конфигурации (или F5 →
   «Клиент 1С-мини (отладка)») — клиент соберётся и запустится под отладчиком.
4. В клиенте откройте элемент и нажмите «Записать» — выполнение остановится
   на точке останова: переменные, стек вызовов, пошаговое выполнение.

Отладка публикатора — конфигурация «Публикатор (отладка)».

## Ограничения MVP

- Клиент редактирует справочники и документы (шапка); табличные части, проведение
  документов и движения регистров — в планах.
- Переименование объекта не переименовывает его C#-модуль.

## Автосборка (GitHub Actions)

При каждом пуше в `main` собираются:
- `onec-config-tree-vsix` — расширение VS Code;
- `onec-mini-win-x64` / `onec-mini-linux-x64` — клиент + публикатор + метаданные.

Скачать: вкладка **Actions** → последний запуск → раздел **Artifacts**.
Исходники расширения: каталог `extension/`.

## Визуальный редактор форм

Клик по форме в дереве (например, `Справочники → Номенклатура → Формы → ФормаЭлемента`) открывает визуальный редактор «как в 1С»:

- **слева** — список элементов формы: перетаскивание мышью, кнопки ↑ ↓ ✕;
- **в центре** — живое превью в стиле управляемой формы 1С;
- **справа** — свойства выбранного элемента (Заголовок, ТолькоПросмотр).

Кнопка «Добавить» предлагает стандартные поля (Код/Наименование или Номер/Дата), реквизиты объекта, табличные части и кнопки (Записать и закрыть, Отмена). Изменения сохраняются автоматически в метаданные объекта (`Формы[].Элементы` в JSON).

Клиент «1С-мини» рендерит форму записи по нарисованному макету: порядок полей, заголовки и признак «Только просмотр» берутся из формы `ФормаЭлемента` (справочники) / `ФормаДокумента` (документы). Если форма не нарисована — поля генерируются автоматически, как раньше.

## Окно выбора информационной базы

Клиент «1С-мини» при запуске показывает окно «Запуск 1С-мини» — по образцу окна запуска 1С:Предприятия:

- список зарегистрированных информационных баз (хранится в профиле пользователя: `%APPDATA%/onec-mini/bases.json`);
- кнопки **1С-мини** (открыть базу), **Конфигуратор** (открывает каталог базы в VS Code), **Добавить…**, **Изменить…**, **Удалить**, **Выход**;
- внизу — путь выбранной базы в формате `File="…";`;
- открытие двойным щелчком.

При первом запуске в список автоматически добавляется найденная рядом демо-база. Если передать путь к базе аргументом командной строки (`Client <каталог>`), окно выбора пропускается — так клиент запускается из отладчика (конфигурация «Клиент 1С-мини (отладка)» передаёт `${workspaceFolder}`).

## Оформление клиента: AXAML + шаблон

Внешний вид Avalonia-клиента настраивается в одном месте — **`client/Client/App.axaml`**: все цвета, размеры и отступы описаны там как классы стилей (`Button.primary`, `TextBlock.sectionHeader`, `StackPanel.formPanel`, `TextBox.field` и т.д.).

- **Статичные окна** описаны разметкой AXAML: `MainWindow.axaml` (главное окно), `ОкноЗапуска.axaml` (выбор базы), `ДиалогБазы.axaml`; логика — в парных `.axaml.cs`.
- **Генерируемые формы** (редактор записи строит поля по метаданным и макету из визуального редактора форм) создаются кодом через фабрики `Шаблон.cs` — но и они не содержат оформления: каждая фабрика лишь навешивает класс стиля из `App.axaml`.

Таким образом изменение стиля в `App.axaml` меняет сразу и статичные окна, и генерируемые формы.

## Рабочий процесс: всё в git

В репозитории хранится всё состояние проекта: метаданные и формы (`metadata/`), оформление и код клиента (`client/`, включая `App.axaml` со всеми стилями), бизнес-логика (`src/BusinessLogic/`), настройки (`.vscode/`). База данных `data/app.db` в git **не хранится** — она воссоздаётся публикацией из конфигуратора.

Поэтому после любых изменений достаточно двух действий:

- **сохранить**: задача VS Code «git: сохранить всё» (Terminal → Run Task) — или вручную `git add -A && git commit -m "..." && git push`;
- **получить**: задача «git: получить обновления» — или `git pull --rebase --autostash` (автоматически прячет и возвращает незакоммиченные правки).

Примечания:
- `bin/`, `obj/`, `node_modules/`, `data/*.db` в git не хранятся — это продукты сборки/публикации, они восстанавливаются сами (базу наполняет публикация).

## Хранение конфигурации (как в 1С)

- **Этап конфигурирования** — метаданные живут в JSON-файлах каталога `metadata/` (исходники, под git).
- **Публикация** (из VS Code или `tools/Publisher`) — помимо таблиц данных, в базу записывается
  полный снимок конфигурации: колонка `Метаданные` таблицы `_Конфигурация`.
- **Клиент**: если рядом с базой есть каталог `metadata/` — читает исходники (режим разработчика);
  если нет — читает снимок из самой `data/app.db`. То есть для работы пользователя достаточно
  двух вещей: клиента и файла базы.

Базы, опубликованные старыми версиями, снимка не содержат — откройте проект в VS Code и выполните
публикацию ещё раз (колонка добавится автоматически через `ALTER TABLE`).

## Целостность при переименовании

Как в 1С: имена можно менять свободно, данные и перекрёстные ссылки не ломаются.

| Что переименовали | Что происходит автоматически |
|---|---|
| Справочник / документ / перечисление | Конфигуратор обновляет ссылочные типы (`СправочникСсылка.Старое` → `...Новое`) во всех реквизитах конфигурации; таблица в базе стабильна (`cat_…`), данные целы |
| Реквизит (шапки, ТЧ, регистра) | Колонка в базе стабильна (`fld_0000001`) и от имени не зависит — переименование базу вообще не трогает. Элементы нарисованных форм обновляются |
| Табличная часть | Таблица `vt_…` стабильна; элементы форм (`ТабличнаяЧасть`) обновляются |
| Значение перечисления | Строка в таблице перечисления переименовывается, все хранимые ссылки в данных обновляются (`UPDATE`) |
| Константа | Строка в таблице `Константы` переносится вместе со значением |

История `ПрежниеИмена` хранится в JSON-метаданных, поэтому переименование корректно
доедет до любой базы, даже опубликованной давно. Код модулей C#, использующий старые
имена (`запись.СтараяКолонка`, `Перечисления.X.СтароеЗначение`), нужно поправить руками —
компилятор сам покажет места.

## Стабильные имена колонок (fld_…)

Как имена таблиц (`cat_0000001`), так и имена колонок реквизитов не зависят от имён
в конфигурации: конфигуратор присваивает каждому реквизиту шапки, табличной части и
регистра стабильное имя `fld_0000001` (поле «Колонка» в JSON). На уровне СУБД — только
`fld_…` (как `_Fld123` в 1С), а клиент, формы и бизнес-логика работают с обычными
именами: маппинг спрятан в слое доступа к данным.

Существующие базы мигрируются автоматически при публикации: колонка, названная по
имени реквизита (или по одному из прежних имён), переименовывается в `fld_…` через
`ALTER TABLE RENAME COLUMN` — данные сохраняются.

## Конфигурация компилируется в DLL и хранится в базе

Как в 1С, платформа отделена от конфигурации:

- при публикации конфигуратор генерирует код, выполняет `dotnet build src/BusinessLogic`
  и кладёт **BusinessLogic.dll + PDB в саму базу** (таблица `_Сборки`);
- **клиент больше не ссылается на бизнес-логику** и не пересобирается при её изменении:
  открывая базу, он загружает конфигурацию из неё (`AssemblyLoadContext`), модули C#,
  события и команды форм работают из этой DLL;
- PDB рядом — точки останова в модулях работают при отладке;
- если конфигурация не компилируется, публикация прерывается с текстом ошибок —
  битая DLL в базу не попадёт;
- базы, опубликованные до этой версии, нужно опубликовать заново (клиент попросит).

Требование: на машине конфигуратора установлен .NET SDK (он и так нужен для клиента).

## Произвольные AXAML-формы

Кроме генерируемых форм (JSON из дизайнера) объект может иметь **произвольную форму** —
обычное окно Avalonia, свёрстанное вручную в AXAML прямо в конфигурации:

- файл кладётся в `src/BusinessLogic/Forms/*.axaml` (+ code-behind) и компилируется
  в ту же DLL конфигурации — **previewer Avalonia в VS Code / Visual Studio работает**;
- класс помечается атрибутом и реализует интерфейс платформы:

```csharp
[ПроизвольнаяФорма("Справочник.Склады")]
public partial class ФормаСклада : Window, IПроизвольнаяФорма
{
    public void Инициализировать(КонтекстФормы контекст) { ... }
}
```

- клиент при открытии объекта сам выбирает: есть произвольная форма в DLL — открывается
  она, нет — генерируемая;
- `КонтекстФормы` даёт форме данные (`Запись` с полями и табличными частями) и конвейер
  платформы `Записать(запись, провести)` — ПередЗаписью, проведение, автонумерация,
  движения работают как в генерируемых формах (общий `СервисЗаписи`);
- пример — `src/BusinessLogic/Forms/ФормаСклада.axaml` (справочник «Склады»).

**Превью форм конфигурации**: превьюеру Avalonia нужен исполняемый проект, ссылающийся
на проект с формой. Клиент на BusinessLogic не ссылается (конфигурация загружается из
базы), поэтому в решение входит хост превью `tools/FormsPreview`. Один раз соберите его
(`dotnet build tools/FormsPreview` или сборка всего решения) — и превью AXAML-файлов из
`src/BusinessLogic/Forms` заработает; в Visual Studio при необходимости выберите проект
FormsPreview в выпадающем списке на панели дизайнера.

## Модели форм и экспорт из дизайнера

Для произвольных форм публикатор генерирует **модели** (`Generated/Модели.g.cs`):

- свойства реквизитов с `INotifyPropertyChanged` (`Справочник_Склады_Модель`, `Документ_ПоступлениеТоваров_Модель`);
- `ObservableCollection` строк табличных частей;
- `ICommand` для кнопок форм (`ЗаполнитьСуммыКоманда`) — выгрузка в запись → метод модуля → загрузка результата, ошибки в свойство `Ошибки`;
- `Загрузить(запись)` / `Выгрузить(запись)` для обмена с конвейером записи.

В AXAML это даёт **компилируемые биндинги** (включены в проекте по умолчанию):

```xml
<Window xmlns:m="using:BusinessLogic" x:DataType="m:Справочник_Склады_Модель">
  <TextBox Text="{Binding Наименование}"/>
  <Button Content="Заполнить" Command="{Binding ЗаполнитьСуммыКоманда}"/>
```

Ошибка в пути биндинга обнаруживается при публикации, а не в рантайме.

**Экспорт из дизайнера**: кнопка «Экспорт в AXAML» в редакторе форм создаёт
`src/BusinessLogic/Forms/<Объект>_<Форма>.axaml(.cs)` — рабочую заготовку по разметке
дизайнера (поля, группы, страницы, таблицы ТЧ со строками, кнопки команд, проведение).
Ссылочные поля в заготовке — текстовые (помечены TODO), их выбор дорабатывается вручную.
После публикации клиент открывает эту форму вместо генерируемой.

## Редактор форм: макет как в 1С

Редактор формы устроен как в Конфигураторе:

- **сверху слева** — дерево элементов формы (иерархия: группы, страницы, поля, таблицы);
- **сверху справа** — закладка «Реквизиты»: все реквизиты объекта с типами, стандартные
  (Код/Наименование, Номер/Дата) и табличные части (раскрываются до своих реквизитов);
  уже размещённые на форме показаны приглушённо;
- **снизу** — превью формы с вкладками «Форма | Модуль» («Модуль» открывает модуль C#);
- свойства выделенного — в палитре справа (правая боковая панель VS Code).

**Перетаскивание как в 1С**: реквизит или табличную часть можно перетащить из закладки
«Реквизиты» прямо на превью формы (в т.ч. внутрь группы/страницы) или в дерево элементов
(на контейнер — внутрь, на элемент — перед ним). Двойной клик по реквизиту добавляет его
в конец формы. Повторный бросок уже размещённого реквизита дубль не создаёт — выделяется
существующий элемент.

**Закладка «Команды»** (рядом с «Реквизитами»): стандартные команды («Записать и закрыть»,
«Отмена») и команды объекта — публичные методы его модуля C# (кроме стандартных
переопределений ПередЗаписью/ПриЗаписи/ПриЗаполнении/ОбработкаПроведения). Перетащите
команду на форму — появится кнопка; повторный бросок дубль не создаёт.

**Перестановка прямо в превью**: поля, таблицы, кнопки, группы и надписи можно
перетаскивать мышью прямо по превью формы — перед другим элементом, внутрь группы или
страницы, либо в пустое место (в конец формы).

**Свойства поля как в 1С** (палитра справа, группы «Основные» и «Использование»):
Имя, Вид, ПутьКДанным, Тип значения, Заголовок, ПоложениеЗаголовка (Авто/Лево/Верх/Нет),
Видимость, Доступность, ТолькоПросмотр, МногострочныйРежим, РежимПароля. Свойства
действуют и в превью дизайнера, и в клиенте, и при экспорте в AXAML.

**Дерево как в 1С**: корневой узел **«Форма»** (его свойства — Заголовок окна,
Ширина, Высота; 0 = автоматически), под ним **«Командная панель»** со всеми кнопками
формы (у кнопки есть свойство **КнопкаПоУмолчанию** — выделенная кнопка), дальше —
элементы. У **Таблицы** дочерние узлы — **колонки** (как ПолеКолонки): у каждой свои
Заголовок, Ширина, Видимость, ТолькоПросмотр; колонки можно переставлять (▲▼),
скрывать и удалять — состав хранится в элементе (`Колонки`), клиент и AXAML-экспорт
строят таблицу по нему (значения реквизитов скрытых колонок при записи не теряются).
Колонку можно выделить и кликом по её заголовку прямо в превью.

**Контекстное меню** в дереве элементов (ПКМ, как в 1С): Добавить группу/страницы/
надпись, Переместить вверх/вниз, Удалить, Свойства (открывает палитру справа).

**Форма списка** (`ФормаСписка`) рисуется в том же дизайнере, но по правилам списка:
элемент **«Список»** с колонками (для документа — включая «Проведен»; у колонки —
Заголовок, Ширина, Видимость, `ПутьКДанным: Список.<Реквизит>`), командная панель
со стандартными командами списка (**Создать, Изменить, Удалить, Обновить**), строка
поиска в превью. Реквизит из панели перетаскивается на форму — появляется колонка;
удалённая колонка снова становится свободной. Клиент строит список по этой форме:
состав/порядок/заголовки/ширины колонок и видимость кнопок командной панели
(формы нет — всё по умолчанию, как раньше).

## Палитра свойств (правая панель)

Свойства показываются в **единой палитре в правой боковой панели VS Code** — как в
Конфигураторе 1С (нужен VS Code 1.106+):

- выделение в дереве конфигурации (объект, реквизит, табличная часть, форма, значение
  перечисления…) — палитра показывает его свойства: имя, синоним, комментарий, тип,
  таблица БД, модуль;
- выделение элемента в редакторе форм — палитра показывает свойства элемента: заголовок,
  только просмотр, группировка, команда кнопки и события с кнопкой «→» к коду;
- правки применяются сразу (дерево и превью формы обновляются на лету);
- команда «Свойства» открывает/фокусирует палитру; если правая панель скрыта —
  включите её: Вид → Внешний вид → Вторичная боковая панель (Ctrl+Alt+B).

## Отладка модулей C#

Точки останова в модулях (`src/BusinessLogic/Modules/*.cs`) работают в конфигурации
запуска **«Клиент 1С-мини (отладка)»** (F5 → выбрать её в списке).

Как это устроено:

- перед запуском собираются клиент и бизнес-логика (`build-debug` в tasks.json);
- **под отладчиком** клиент загружает `BusinessLogic.dll` **с диска** из
  `src/BusinessLogic/bin/Debug` текущей папки — пути и контрольные суммы в PDB всегда
  совпадают с исходниками, точки срабатывают ровно на своих строках;
- **без отладчика** (обычный запуск) конфигурация, как и положено, берётся из базы
  (таблица `_Сборки`, кладётся туда при публикации вместе с символами).

Откуда взята сборка, видно в консоли отладки: строка `[Конфигурация] …`.

Если отладчик пишет «исходный файл отличается» / предлагает `requireExactSource: false` —
исходники на диске разошлись с тем, что в базе: выполните `git pull` и/или публикацию
заново. `requireExactSource: false` не ставьте — точки начнут срабатывать «мимо» строк.

Сообщение `[Control] PlatformImpl is null, couldn't handle input` — безвредное
предупреждение Avalonia при закрытии окна, на работу не влияет.

## События элементов формы

В палитре свойств дизайнера форм у элементов появился раздел **«События»** — как в 1С,
обработчик события — метод C# в модуле объекта:

| Элемент | Событие | Когда вызывается (Avalonia) |
|---|---|---|
| Поле | ПриИзменении | значение изменено: выбор в списке (SelectionChanged), флажок (IsCheckedChanged), дата (SelectedDateChanged); текст/число — при уходе с поля, если текст изменился (не на каждый символ) |
| Поле | ПриВходе | поле получило фокус (GotFocus) |
| Поле | ПриВыходе | поле потеряло фокус (LostFocus) |
| Таблица | ПриИзменении | изменена любая ячейка, добавлена или удалена строка |

- Кнопка **«→»** рядом с событием переходит к обработчику в модуле: метод создаётся
  автоматически, если его ещё нет, и курсор встаёт на него. Пустое имя заполняется
  по правилу 1С: `<Элемент><Событие>` (например, `КонтрагентПриИзменении`).
  Такой же переход «→» есть у свойства **«Команда (метод C#)»** кнопок.
- Обработчик получает текущее состояние формы (поля + строки ТЧ); его изменения сразу
  возвращаются на форму. Сигнатура — как у команд: типизированная запись, `ЗаписьОбъекта`
  или без параметров.
- Программная установка значений (загрузка формы, возврат результатов обработчика)
  события не вызывает — зацикливание исключено.

Пример в демо-конфигурации (ПоступлениеТоваров):

```csharp
// ПриИзменении поля «Контрагент»: подставить склад по умолчанию
public void КонтрагентПриИзменении(ДокументПоступлениеТоваровЗапись запись)
{
    if (string.IsNullOrWhiteSpace(запись.Склад))
        запись.Склад = Справочники.Склады.Сортировка("Код").ВыбратьПервую()?.Ссылка ?? "";
}

// ПриИзменении таблицы «Товары»: автопересчёт цен и сумм
public void ТоварыПриИзменении(ДокументПоступлениеТоваровЗапись запись) => ЗаполнитьСуммы(запись);
```

## Команды формы и декорации

Как в 1С: кнопка на форме ссылается на команду, а команда — на обработчик в модуле объекта.

1. В дизайнере форм добавьте кнопку **«Команда модуля (C#)»** и в свойстве
   **«Команда (метод C#)»** укажите имя метода.
2. В модуле объекта объявите публичный метод с этим именем — параметр: типизированная
   запись, `ЗаписьОбъекта` или без параметров:

```csharp
// кнопка «Заполнить цены и суммы» на форме поступления
public void ЗаполнитьСуммы(ДокументПоступлениеТоваровЗапись запись)
{
    decimal итог = 0;
    foreach (var строка in запись.Товары)
    {
        if (строка.Цена == 0)
            строка.Цена = Справочники.Номенклатура.Отбор("Ссылка", строка.Номенклатура).ВыбратьПервую()?.Цена ?? 0;
        строка.Сумма = строка.Количество * строка.Цена;
        итог += строка.Сумма;
    }
    запись.СуммаДокумента = итог;
}
```

Команда получает текущее состояние формы (поля + строки ТЧ), её изменения сразу
отображаются на форме — без записи в базу. Ошибки и исключения показываются под формой.
Внутри команды доступны запросы (`Справочники.X`, `Запрос.Из`).

**Декорация-надпись** — элемент «Надпись» в дизайнере: пояснительный текст на форме
(класс стиля `decoration` в App.axaml). Пример — форма документа ПоступлениеТоваров
в демо-конфигурации: горизонтальная группа «Номер + от», надпись-подсказка,
кнопка «Заполнить цены и суммы».

## Поведение полей по типу данных

Как в 1С, вид поля на форме определяется типом реквизита — и в превью дизайнера, и в клиенте:

| Тип | Поле на форме |
|---|---|
| Дата | календарь (CalendarDatePicker) + поле времени ЧЧ:ММ:СС |
| Число | выравнивание вправо, принимает только цифры/разделитель/минус; в базу уходит число, не строка |
| Булево | флажок |
| Ссылка | выбор из списка |

- У нового документа дата заполняется текущей автоматически.
- Числовые ячейки табличных частей — тоже числовые (вправо, с фильтрацией ввода).
- Оформление настраивается в App.axaml по классам: `dateField`, `timeField`, `numField`.

## Группы и страницы на формах

Дизайнер форм поддерживает иерархию элементов, как дерево элементов в Конфигураторе 1С:

- **Группа** — объединяет элементы; свойство «Группировка»: *Вертикальная* или *Горизонтальная*
  (горизонтальная ставит поля в ряд), необязательный заголовок.
- **Страницы** — контейнер вкладок; внутрь добавляются только элементы **Страница**,
  каждая — отдельная вкладка со своим заголовком и содержимым.
- Вложение — перетаскиванием в дереве: бросьте элемент **на** группу/страницу, чтобы вложить,
  **между** элементами — чтобы изменить порядок. ▲/▼ двигают элемент в пределах родителя.
- Превью показывает группы и работающие вкладки; клиент строит такую форму из метаданных
  (вкладки — TabControl, группы — панели, всё оформление — в App.axaml через классы
  `formGroup`, `formTabs`, `formPage`, `groupTitle`).

Пример — форма Номенклатуры в демо-конфигурации: Код и Наименование сверху, ниже вкладки
«Основное» (с горизонтальной группой «Единица измерения + Ставка НДС») и «Характеристики» (ТЧ).

## Запросы в коде (отбор и сортировка)

В любом месте бизнес-логики — типизированные запросы через точку:

```csharp
// проведённые поступления контрагента за период, новые сверху
var документы = Документы.ПоступлениеТоваров
    .Отбор("Контрагент", контрагент)
    .Отбор("Дата", ">=", "2026-01-01")
    .Отбор("Проведен", 1)
    .Сортировка("Дата", убывание: true)
    .СТабличнымиЧастями()                 // подгрузить строки ТЧ
    .Выбрать();                           // List<ДокументПоступлениеТоваровЗапись>

foreach (var д in документы)
    foreach (var стр in д.Товары)         // типизированные строки
        Что-то(стр.Номенклатура, стр.Количество);

var ромашка = Справочники.Контрагенты
    .Отбор("Наименование", "Подобно", "%ромаш%")   // LIKE без учёта регистра, и для кириллицы
    .ВыбратьПервую();
```

- Операторы отбора: `=`, `<>`, `>`, `>=`, `<`, `<=`, `Подобно` (маска `%`); условия объединяются по И.
- `Сортировка(поле, убывание)`, `Первые(N)`, `ВыбратьПервую()`.
- Нетипизированный вариант для любого объекта (включая регистры):
  `Запрос.Из("РегистрНакопления.ОстаткиТоваров").Отбор("Склад", с).Выбрать()`.
- Поля указываются по именам реквизитов — в SQL они автоматически превращаются в стабильные
  колонки `fld_…`; значения передаются параметрами (без SQL-инъекций).

## Проведение документов и регистры накопления

Как в 1С: документ при проведении формирует движения по регистрам накопления.

- В форме документа — кнопки **«Провести и закрыть»** (главная) и **«Записать»**
  (запись без проведения; снимает документ с проведения и удаляет его движения).
- В модуле документа переопределите `ОбработкаПроведения` (типизированный обработчик):

```csharp
public override void ОбработкаПроведения(ДокументПоступлениеТоваровЗапись запись, Движения движения, Отказ отказ)
{
    foreach (var строка in запись.Товары)               // типизированные строки ТЧ
    {
        var движение = движения.ОстаткиТоваров.ДобавитьПриход();
        движение.Номенклатура = строка.Номенклатура;
        движение.Склад       = запись.Склад;
        движение.Количество  = строка.Количество;
    }
}
```

- Движения формируются **до** записи: при `отказ.Установить(...)` ничего не записывается.
- Перепроведение перезаписывает движения (старые удаляются по «Регистратор»), удаление
  документа удаляет и движения, и строки ТЧ.
- В списке документов — колонка «Проведен» (✓).
- Для регистров накопления в клиенте есть кнопка **«Остатки»**: измерения + суммы
  ресурсов (Приход − Расход), нулевые остатки скрываются.

## Удобства списков

- **Поиск** (поле справа от кнопок, фокус — `Ctrl+F`): фильтр по подстроке во всех
  колонках без учёта регистра; ищет и по представлениям ссылок (например, по
  наименованию контрагента или синониму значения перечисления). Статус показывает
  «показано M из N».
- **Сортировка** — клик по заголовку колонки (повторный клик — обратный порядок,
  индикатор ▲/▼). Числа сортируются численно, остальное — по алфавиту.
- При смене объекта в дереве поиск и сортировка сбрасываются.

## Табличные части в клиенте

Форма записи показывает табличные части как редактируемые таблицы:

- колонки — по реквизитам ТЧ (строка/число — поле ввода, Булево — флажок, ссылки — выпадающий список с подбором из справочника/перечисления);
- кнопки **«Добавить строку»** и **✕** (удаление строки);
- строки сохраняются вместе с записью («Записать и закрыть») одной транзакцией: DELETE + INSERT по Ссылке владельца, НомерСтроки проставляется автоматически;
- на нарисованной форме ТЧ выводится там, где стоит элемент «Таблица» (с заголовком из макета); без нарисованной формы — все ТЧ после полей.

Пример: документ «Поступление товаров» → таблица «Товары» с подбором номенклатуры.
